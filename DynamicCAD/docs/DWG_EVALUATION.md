# DWG support: evaluation (Milestone 12)

**Decision for v0.9.0: DYNAMIC CAD does not read or write DWG.** AutoCAD drawings are exchanged through DXF,
which DYNAMIC CAD imports (R12–2018) and exports (AutoCAD 2000 format) with its own code.
No DWG compatibility is claimed.

## Why DWG is a separate workstream

DWG is Autodesk's binary format. Its specification is not published by Autodesk, it changes with AutoCAD releases
(R2000, 2004, 2007, 2010, 2013, 2018 formats), and the "DWG" and "TrueView" names are Autodesk trademarks.
Reading it reliably requires either a licensed library or a very large reverse-engineering effort.

## Options

| Option | What it gives | Cost / licence | Risk | Assessment |
|---|---|---|---|---|
| **A. DXF only (current)** | Users in AutoCAD use *Save As → DXF*; DYNAMIC CAD exports DXF that AutoCAD opens | None (own code) | One extra step for users; DXF from some third-party tools is imperfect | **Adopted now.** Fully under our control, no third-party terms |
| B. Open Design Alliance (ODA) Drawings SDK | Read/write all DWG versions, high fidelity, industry standard | Paid annual membership (tier depends on company size and commercial use); requires a membership agreement; binary SDK | Contract terms, yearly cost, SDK integration (~4–8 weeks) | Best route if DWG becomes a sales requirement. **Needs owner approval of cost and agreement before any download.** |
| C. LibreDWG (GNU) | Read (partial write) of many DWG versions | **GPL v3** | GPL would oblige us to publish DYNAMIC CAD source if linked | **Rejected**: incompatible with a proprietary application (master-prompt rule) |
| D. Separate converter process using a GPL tool | DWG → DXF before import | GPL tool must be shipped and offered with source; legal review needed on "separate program" boundary | Legal/licensing ambiguity, version gaps | Not recommended |
| E. Autodesk RealDWG | Native Autodesk library | Commercial licence from Autodesk, royalty terms | Cost, Autodesk approval | Possible but typically more expensive than ODA |
| F. Own DWG reader | Full control | Many person-months; legal review of clean-room process | High technical risk, never complete | Not recommended |

## Recommendation

1. Keep DXF as the exchange format for the first commercial version (Option A). It is tested both ways:
   `test_dxf` (import fixtures generated by the MIT-licensed ezdxf, test-only), `test_dxf_export` (export,
   re-import, handle/owner integrity) and an external audit of exported files with ezdxf (0 errors, 0 fixes).
2. If customers require direct DWG, request an ODA membership quote and review the agreement
   (Option B) — this is a paid dependency and needs explicit approval.
3. Before any DWG claim: test against a set of real customer drawings (at least 50 files, every AutoCAD version
   in use at Dynamic Engineers), compare entity counts, extents, layers and visual output, and publish the
   results in STATUS.md.

## What still needs manual verification

DXF files exported by DYNAMIC CAD have **not yet been opened in AutoCAD** (no AutoCAD is available in the
build environment). Please open `File → Export DXF` output in your licensed AutoCAD and report any message
AutoCAD shows (for example "drawing needs repair"). Exported files use AutoCAD 2000 structure (handles,
owners, block records, layouts, named object dictionary), which AutoCAD 2000 and every later release read.
